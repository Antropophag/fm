# ADDRESS-REGISTER-001 — Адресный перечень

## Простыми словами
Отдельный раздел с широкой таблицей объектов для сотрудников, привыкших сверять данные в Excel. Каждый выбирает свои колонки, их порядок и ширину; настройки привязаны к аккаунту и работают на другом устройстве. Факты читаются из действующих источников FMonitor, изменения объектов выполняются в их карточках.

## Авторизация и маршрут
A1. GET/HEAD `/pilot/address-register` доступен активному authenticated actor с canonical `objects.read`. Гость получает303 на native login с return URL; пользователь без права —403. POST `/pilot/address-register/preferences` требует то же право и native CSRF. Actor определяется только серверной identity, client userId запрещён. HEAD не возвращает body. Ответы с пользовательскими данными no-store. Остальные методы405.

## Данные и чтение
A2. Одна строка на объект локального каталога `fm_maintable`, без размножения по монтажникам/версиям/документам. Все запросы read-only; не создают/исправляют process facts. Регномер/завномер/адрес/подъезд учитывают effective manual edits. Технические поля берутся из проверенного detail snapshot плюс текущих исправлений. Native текущие закрепления/применённые составы имеют приоритет; подготовленный неподписанный состав не выдаётся за действующий. Без достоверного источника выводится «—». Фактическое начало — canonical case.actual_start_date, не дата upload. Статус/процент/факт окончания/ПТО/декларация используют действующие projections. Объект без дела допускается как «Нет монтажного дела», без неработающей ссылки на карточку. Проекции не подтягивают секреты, персональные кадровые/платёжные поля или произвольные116legacy columns.
A3. Поиск q по адресу/регномеру/завномеру/подъезду (до120символов, %/_/\ как literal), фильтр стадии, серверная пагинация50строк с детерминированным порядком адрес/подъезд/id. Не загружать весь каталог в браузер; enrich только текущую страницу пакетными запросами. Фильтры сохраняются при переходе страниц; новый поиск начинает с1. Пустая выборка объясняет сброс. Неправильные scalar/query/page inputs400; dependency failure503 без SQL/stack/secrets. Отдельная пользовательская сортировка, Excel export и inline domain editing в эту версию не входят.

## Персональные настройки
A6. Public seam `FMonitor2\AddressRegister\ColumnPreferences::__construct(string $root, callable $authorized)`, `read(int $actor):array`, `save(int $actor,int $expectedRevision,array $visible,array $widths):array`. Result exact keys revision, visible, widths. Default revision0, widths содержит widths для всего каталога. `Columns::defaults():array` and `Columns::catalogue():array` supply closed schema. Данные сервера в private durable state subtree address-register-preferences, отдельно от sessions, не истекают при logout. Идентичность пользователя задаёт isolated key, повторный экземпляр/браузер читает прежние настройки. Это presentation state; business facts не изменяются. Все разрешённые настройки проверяются server-side; empty/unknown/duplicate keys, address not first, invalid widths/types/revision, unsupported fields запрещены без изменения прежних bytes. DomainException access denied, InvalidArgumentException invalid data, `PreferenceConflict` stale revision, RuntimeException unavailable/corrupt storage. UI не показывает persisted success до подтверждения server. Конфликт возвращает409 с предложением загрузить актуальные настройки, validation422, CSRF400. Идентичный повтор при expected current revision не добавляет revision; stale expected revision отвергается даже с одинаковыми values.
A7. Save под per-user lock перечитывает revision, atomically publishes полный snapshot через temporary file+flush/fsync+rename, не допускает partial JSON/lost updates; revision increments1 при изменении. Private root/subdirs0700 и files0600; bounded input, symlink/nonregular path rejected. Хранится immutable история принятых версий; read/GET/default не создаёт бизнес-фактов. Испорченный snapshot не сбрасывает настройки молча; fail closed. Backup/restore существующего runtime state сохраняет preferences subtree; новая SQL migration не нужна. Нельзя хранить preferences в public assets, Git, session-only или global browser localStorage.
