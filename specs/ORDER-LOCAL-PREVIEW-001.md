# ORDER-LOCAL-PREVIEW-001

## Простыми словами
Один вычисляемый реквизит вместо пояснительного блока. Основные действия распоряжения находятся в основном интерфейсе, подсказка объясняет следующий шаг. Внутренний номер ФН отличается от номера согласованного документа в 1С ДО.

## Разрешённый локальный показ
Владелец 25.11.2026 явно разрешил реализацию и показ до гейтов. Существующие права, история, изоляция данных и запрет полного local suite сохраняются. Формальная интеграция после обратной связи.

## Критерии
- UI: карточка содержит один факт «Нормативный период — N календарных дней» (договорный интервал включительно); неизвестный интервал не выдумывается. Нет повторных пояснений/дат в этом реквизите.
- Actions: сохранить состав, сформировать шаблон, загрузить/исправить оригинал доступны в основном layout. Кнопка шаблона синяя. В следующем шаге только пояснение и допустимая ссылка на последний сформированный шаблон, без дублирующих workflow actions.
- Registry: существующий транзакционный регистр выдаёт уникальный возрастающий ID; отображаемый внутренний номер ФН{ID}. Один order сохраняет номер при скачивании, повторе и исправлении оригинала. Номера не переиспользуются, пропуски допустимы.
- Template: POST формирования присваивает текущую московскую дату и сохраняет конкретные PDF bytes с номером и составом. GET последнего шаблона возвращает те же bytes, дату и номер без новых фактов. Новое явное формирование сохраняет прежнюю историю. Ошибка формирования не уничтожает последний успешный файл. Доступ проверяется по существующим полномочиям и объекту.
- Upload: UI не запрашивает дату распоряжения и checkbox подтверждения. Нажатие загрузки — явное действие пользователя. Сервер берёт дату последнего успешного шаблона, при отсутствии — день первого формирования оригинала; повтор не меняет дату. Дата начала работ остаётся отдельным обязательным полем.
- External number: обязательная строка «Номер в 1С ДО», до 255 Unicode символов, с обрезкой краевых пробелов; пустая/слишком длинная строка отвергается до новых фактов. Кириллица, ведущие нули и пунктуация сохраняются. Значение привязано к принятой редакции и отображается в истории. Старые оригиналы без этого реквизита показывают неизвестное значение, не получают выдуманный номер.
- History/replay: неизменный повтор не дублирует оригинал/открытие/номер; изменённый номер на том же requestId конфликтует. Исправление сохраняет прежний оригинал, внешний номер и первоначальное начало работ. Отказ по доступу не сохраняет документ/номер.
- Local: показать карточку, состав и загрузку; проверить реальный цикл PDF/download/upload/history на isolated fixtures. Никаких новых рабочих бизнес-фактов ради проверки. Сохранить исходный стенд.

## Уточнение владельца — дата начала в шаблоне,25.11.2026
Дату начала работ пользователь выбирает перед формированием шаблона. Плановая дата объекта — только первоначальная подстановка; последнее успешно сформированное значение подставляется при следующем открытии. HTTP POST формирования требует appendixStartDate, корректную календарную дату; будущая дата разрешена. Пустое, отсутствующее, массив/дубликат или несуществующая дата отклоняются без новых фактов. Выбранная дата сохраняется с неизменяемым PDF и впечатывается в колонку «Дата начала работ» приложения. Плановые и договорные даты объекта при этом не изменяются; формирование не открывает работы. Повторное скачивание сохраняет исходные bytes/дату.
При первоначальной загрузке оригинала подставляется дата из последнего успешного шаблона; она остаётся доступной для уточнения по согласованному оригиналу. При исправлении подставляется дата принятого оригинала. Для старых шаблонов без сохранённой даты используется прежний fallback, а не выдуманный исторический факт. Сформировать шаблон из карточки можно только через форму выбора даты, без скрытого обхода этого поля. Это обратная связь по тому же локальному preview; гейты/CI остаются отложенными.

Нет глобальной кнопки сохранения внизу всей страницы, смешивающей независимые операции. Подсказка — короткий текст внутри соответствующего шага, без правой карточки/дублирующих действий. ## Прямой вход в новое распоряжение
Во вкладке «Документы» карточки объекта при существующем загруженном оригинале и отсутствии pending распоряжения доступна primary-кнопка «Новое распоряжение», ведущая в существующий selection flow. ## Структура сроков и готовности
Плановые сроки (начало/завершение/один вычисляемый норматив) и фактические даты (начало/ПТО) сгруппированы отдельно. Перенос срока вынесен из ячейки планового завершения в самостоятельную полноширинную строку, где дата дляОТиЗ, PDFсправки/состояние отсутствия и кнопка справок расположены вместе. Документная/процессная готовность, даты оборудования и вторичные сведения открытия структурированы по смыслу, без вложенных карточек. Права/ссылки/данные/история/прочие вкладки и completioncontrols сохраняются. Наузкомэкране группы естественно складываются, кнопка не отделяется отконтекста.
