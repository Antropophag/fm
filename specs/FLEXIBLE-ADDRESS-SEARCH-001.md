# FLEXIBLE-ADDRESS-SEARCH-001

## Простыми словами

Все действующие поля поиска адреса понимают обычную запись улицы, дома, корпуса/строения и подъезда. Пользователю не нужно воспроизводить пунктуацию и сокращения из базы. Ошибка в букве названия не должна скрывать адрес, но цифры не исправляются наугад. Поиск не изменяет данные.

## Public seams and scope

Авторизованный пользователь выполняет GET существующего списка: `/pilot/objects`, `/pilot/address-register`, `/pilot/construction-control`, `/pilot/completion-register`, `/pilot/otiz` и `/pilot/otiz/objects`, `/pilot/otiz/calculations/<id>`; офлайн-пользователь фильтрует сохранённые объекты. Общий read-only поиск применяется также к используемому ObjectRegister без изменения retired rapid-pilot UI. Существующие права и область mine/all остаются обязательными.

## Acceptance

A1. Регистр, ё/е, повторные/неразрывные пробелы, запятые и точки между компонентами не меняют результат. Поиск по одному имени/части имени, нескольким словам в любом порядке и неполному адресу разрешён. Тип улицы (`ул/улица`, `просп/проспект/пр-т`, `пер/переулок`, `ш/шоссе`, `наб/набережная`, `б-р/бульвар`, `пр-д/проезд`) нормализуется. Если тип указан в запросе и известен в записи, разные типы не смешиваются; отсутствующий в записи тип не мешает поиску по имени. Знак № перед номером необязателен, в том числе в отдельном поле подъезда; односимвольные служебные слова внутри имени не вырезаются.

A2. Дом (`д/дом`), корпус (`к/корп/корпус`), строение (`с/стр/строение`), подъезд (`п/под/подъезд/подезд`) распознаются с точками и без пробелов. Явные компоненты допускают любой порядок. Числовой хвост после названия без маркеров означает дом, корпус, подъезд (до трёх позиций); явный подъезд позволяет опустить корпус. Числа внутри имени улицы (`1905 года`, `50 лет Октября`, `1-я Тверская-Ямская`) сохраняются частью имени. Запросы без имени (`д12 к2 п3`, `подъезд 3`) разрешены.

A3. Каждый заданный числовой компонент совпадает точно: дом12 не дом112/120; корпус2 не корпус12/строение2; подъезд3 не13. Литера, дробь и строение значимы: 12а,12б,12/1,12/2 различаются. Отсутствующий в запросе компонент не ограничивает выдачу. Неизвестный в записи компонент не изобретается; если он задан, запись не совпадает. Конфликтующие явные компоненты не превращаются в широкий поиск. Нечёткий поиск никогда не применяется к числам и идентификаторам.

A4. Небольшая опечатка в кириллическом имени из пяти и более букв допускается (например, `березовя` находит `Берёзовая`); короткие слова не расширяются произвольно. Все значимые слова запроса должны находиться в одном адресе, нельзя собирать совпадение из разных объектов. Составные названия с дефисами/пробелами поддерживаются. Точное совпадение не пропадает при наличии приблизительных. Существующая детерминированная сортировка списков сохраняется.

A5. Сохраняются прежние поля поиска каждого раздела: регномер, заводской номер, внутренний ID там, где он уже поддерживался, реквизиты декларации и имя/табельный номер в расчёте. `%`, `_`, обратный слеш и кавычки остаются буквальными символами, не SQL/regex wildcard. Пустой/пробельный запрос показывает обычный список; неизвестный запрос даёт честный ноль. Существующие ограничения длины/типа входа действуют. Ввод не исполняется как код, regex или SQL.

A6. Серверный поиск применяется ко всему разрешённому набору до COUNT/пагинации и одинаково определяет total, строки и связанные отфильтрованные итоги. Явно глобальная economics summary старого ObjectRegister остаётся глобальной по OTIZ-OBJECT-REGISTER-PAGING-001; фильтрация не меняет её финансовый смысл. Совпадение за первой страницей доступно. Остальные фильтры, стабильные границы страниц, возврат из карточки и дебаунс/фокус ввода сохранены. Обновлённые эффективные адрес/подъезд доступны следующему поиску; отдельная переиндексация оператором не требуется.

A7. Офлайн-поиск работает без сети по фактически сохранённым объектам и тем же адресным правилам, без расширения actor/device области. Расчёт ищется по его собственным данным; совпадение объекта/ребёнка сохраняет целую группу. Если снимок не содержит подъезда, поиск не подставляет современное значение задним числом.

A8. GET/HEAD/офлайн-фильтр не создают фактов, не меняют адреса, историю, расчётные суммы или права; SQL-поиск не снимает остальные predicates. Нет отправки адресов стороннему API, платных сервисов или нового отдельного search daemon. Используется готовый проверяемый search component с закреплённой версией/лицензией. Полная проекция карточек для поиска не загружается; измеряется стоимость поиска на 10000 лёгких синтетических записей, память/время записываются в evidence. Никакого скрытого лимита кандидатов, теряющего совпадения.

## Independent examples

Пусть A=`ул. Берёзовая, д. 12, корп. 2`, подъезд3; B тот же адрес, подъезд13; C дом112 корпус2 подъезд3; D дом12 строение2 подъезд3. `березовая 12 2 3`, `к2 берёзовая п3 д12`, `БЕРЕЗОВАЯ, Д.12К2 П.3` находят A, исключают B/C/D. `березовая` находит A/B/C/D. `березовя д12 к2 п3` находит A. `12/1` не совпадает с12/2; `улица 1905 года д7` сохраняет1905 как часть имени. В наборе с более50 строками совпадающий адрес на позиции60 не теряется. Примеры — иллюстрации общей грамматики, не whitelist адресов.
