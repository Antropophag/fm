# Официальный API ФИАС/ГАР для постоянного XLSX-импорта

Дата исследования: 18 ноября 2026 года. Проверены только официальные материалы
ФНС России и принадлежащие ей API-узлы. Реальные адреса не отправлялись, токен не
получался, заявки и платные вызовы не выполнялись.

## Вывод

Официальный SPAS API ФИАС — обоснованный первый кандидат на бесплатную замену
DaData: ФНС предоставляет его **безвозмездно**, а документированный раздел
`Conversion` принимает массив строковых или структурированных адресов, выполняет
фоновую массовую конвертацию и возвращает для каждой записи идентификатор объекта,
GUID ФИАС, полное имя либо ошибку. Это предусмотренный поставщиком batch-механизм,
но его заявленное назначение — переход КЛАДР → ГАР; применимость к произвольным
строкам XLSX ещё нужно подтвердить у ФНС.
[Условия использования](https://fias.nalog.ru/docs/Условия%20использования%20API-сервисов%20ФИАС.pdf),
[официальный раздел API](https://fias.nalog.ru/Frontend/Api),
[руководство SPAS v2.0](https://fias.nalog.ru/docs/SPASDesc%20v2.0.docx).

Однако готовность для постоянного автоматического импорта пока **UNKNOWN**.
Безвозмездность не означает свободный анонимный или неограниченный доступ:
требуется мастер-токен, действуют лимиты, а документация не описывает аналог
DaData `qc_house`/confidence для автоматической оценки качества сопоставления.
До получения собственного токена и прогона обезличенной контрольной выборки нельзя
обещать полную замену DaData или автоматически принимать каждый найденный адрес.

## Наблюдаемые официальные условия

- Для доступа нужно заполнить форму, отправить её на `api.fias@tax.gov.ru` и
  получить от ФНС мастер-токен; срок рассмотрения — до 30 дней. Автоматическое
  получение токена и передача его третьим лицам запрещены.
  [Условия использования](https://fias.nalog.ru/docs/Условия%20использования%20API-сервисов%20ФИАС.pdf).
- Функциональность предоставляется безвозмездно. Отдельных тарифов или платы в
  опубликованных условиях нет. Текущий лимит — 100 запросов в минуту и 10 000
  запросов в день; ФНС вправе менять доступный объём в одностороннем порядке.
  [Условия использования](https://fias.nalog.ru/docs/Условия%20использования%20API-сервисов%20ФИАС.pdf).
- Форма запрашивает ОГРН, организацию, продукт и URL, до десяти IP-адресов без
  масок/диапазонов, прогноз пользователей, дату промышленного запуска и описание
  сценариев. В форме тип пользователя ограничен юридическим лицом или ИП, хотя
  текст условий определяет разработчика также как физическое лицо. Это внутреннее
  расхождение официальных документов требует разъяснения ФНС, если заявитель не
  ЮЛ/ИП. [Форма заявки](https://fias.nalog.ru/docs/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%20%D0%B7%D0%B0%D1%8F%D0%B2%D0%BA%D0%B8.docx),
  [условия использования](https://fias.nalog.ru/docs/Условия%20использования%20API-сервисов%20ФИАС.pdf).
- В OpenAPI 3.0 для всех рассматриваемых методов задан API key `master-token` в
  HTTP-заголовке. Пробный `GetRegions` без ключа 18.11.2026 вернул HTTP 403
  «Не указан токен»; содержательные адреса при проверке не передавались.
  [Swagger SPAS v2.0](https://fias-public-service.nalog.ru/api/spas/v2.0/swagger/swagger.yaml).

## Подходящие методы и проверка дома

Фоновый путь массовой обработки документирован как
`CreateConversionTask` → `AddConversionData` → `StartConversionTask` →
`GetConversionTaskStatus` → `GetConvertionResultBlock`. `AddConversionData`
принимает массив с внешним `ext_id`; запись может содержать свободную строку или
части адреса. Результат связывается с исходной записью и содержит `object_id`,
`object_guid`, `full_name` и `error`.
[Руководство SPAS v2.0](https://fias.nalog.ru/docs/SPASDesc%20v2.0.docx),
[Swagger SPAS v2.0](https://fias-public-service.nalog.ru/api/spas/v2.0/swagger/swagger.yaml).

Для одиночной диагностики доступны:

- `SearchAddressItem(s)` — поиск по произвольной строке;
- `SearchByParts` — поиск по структурированному адресу с явной ошибкой, например
  «Не найден дом»;
- `GetAddressItemById` и `GetAddressItemByGuid` — повторное чтение найденного
  объекта; `AddressItem` содержит уровень, GUID, полный адрес и `is_active`;
- `GetDetails` — индекс, коды и кадастровый номер, если они есть;
- `IsDescendant` — проверка принадлежности объекта нужной иерархии.

В руководстве входной класс `House` обозначает здание/сооружение, имеет
`object_level_id = 10`, GUID, основной и два дополнительных номера. Но результат
конвертации возвращает только `object_id`, GUID, полную строку и ошибку, а
`AddressItem` — уровень, активность, полное имя и общую иерархию; отдельные поля
номера/корпуса результата контрактом не гарантированы. Поэтому активный уровень 10
может быть лишь частью правила приёмки. Надёжное сравнение номера, корпуса и
строения требует проверки фактического ответа или дополнительного официального
метода. Это **вывод из схемы**, а не гарантия качества распознавания: ни результат
конвертации, ни `AddressItem` не имеют документированного confidence score.
Неоднозначные, неполные и не-house результаты должны оставаться на ручной проверке.
[Руководство SPAS v2.0](https://fias.nalog.ru/docs/SPASDesc%20v2.0.docx),
[Swagger SPAS v2.0](https://fias-public-service.nalog.ru/api/spas/v2.0/swagger/swagger.yaml).

## Публичный сайт и API разработчика

`https://fias.nalog.ru/Search` — пользовательский веб-интерфейс поиска. Официальный
раздел интеграции отдельно направляет разработчиков на SPAS v2.0 на хосте
`fias-public-service.nalog.ru`, его руководство, условия и форму заявки. Именно
Swagger SPAS является опубликованным контрактом для интеграции и требует
мастер-токен. Наблюдаемый JavaScript публичного сайта также получает принадлежащие
сайту настройки SPAS и передаёт токен в заголовке; это не отдельный безтокенный
контракт. Внутренние учётные данные сайта нельзя извлекать или переиспользовать:
условия запрещают автоматическое получение и передачу мастер-токена.
[Поиск ГАР](https://fias.nalog.ru/Search),
[официальный раздел API](https://fias.nalog.ru/Frontend/Api),
[Swagger UI SPAS v2.0](https://fias-public-service.nalog.ru/api/spas/v2.0/swagger/index.html).

## Блокеры и следующий шаг

Наблюдаемые блокеры: нет выданного проекту мастер-токена; официально заявленное
назначение `Conversion` — переход с КЛАДР на ГАР, поэтому допустимость произвольных
«грязных» строк XLSX и хранения нормализованного результата нужно подтвердить у
ФНС. Руководство показывает полиморфные записи `string` и `parts`, но Swagger
описывает базовый `ConvertionRecord` неполно; это нужно проверить с собственным
токеном. Не опубликованы максимальные записи/байты в блоке и задаче, параллелизм,
retention, SLA и семантика неоднозначного поиска; лимит задан для запросов, а не
строк. Не измерены точность, латентность и расход квоты; условия могут меняться без
уведомления. Основной портал периодически не отвечал через браузерный канал, хотя
18.11.2026 официальные PDF/DOCX, страница API и versioned Swagger скачивались
напрямую. Для атомарного импорта это требует timeout/retry и staging-диагностики:
при недоступности провайдера применение всего каталога блокируется.

Точный следующий шаг: уполномоченный владелец продукта заполняет официальную форму
на ЮЛ/ИП, явно указывает сценарий «серверная фоновая нормализация и хранение
результатов адресов из XLSX», ожидаемый суточный объём и исходящие IP, а также
просит подтвердить допустимость сценария, лимиты batch/задач и трактовку
неоднозначности; затем сам направляет заявку ФНС. После выдачи токена — отдельный
read-only spike на небольшой обезличенной эталонной выборке:
проверить batch lifecycle, house-level 10, номера и дополнительные номера,
`is_active`, ошибки/неоднозначность, реальный расход квоты и недоступность. До этих
результатов архитектура должна держать provider adapter и состояние
`requires_review`; реализацию замены DaData считать преждевременной.
