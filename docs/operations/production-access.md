## Обновления

Штатный маршрут на сервере: `cd /opt/fm2 && git pull --ff-only && make update`
под пользователем существующей установки, с её `.env` и каталогом состояния.
В GitLab переносится проверенный `main` из GitHub `Antropophag/fm`.

Для обновлений администратор выделил проекту Runner `web-03-runner` (ID 8),
тег `web-03`, сервер `web-03` (`10.178.80.4`). По сообщению Ильяса Runner
работает от отдельного пользователя `gitlab-runner`.

Файл `.gitlab-ci.yml` запускает `deploy_fm2_production` при push в `main` или
Run pipeline для `main`. Задача проверяет ветку серверного checkout и выполняет
`make status`, затем `git pull --ff-only`, сверяет HEAD с коммитом pipeline,
запускает `make update` и повторяет `make status`. Параллельные выкладки
сериализованы группой `web-03-fm2`. Ошибка любого шага останавливает задачу.

Runner должен видеть существующие `.env`, состояние установки и Docker под
своей системной учёткой. Их отсутствие — причина остановки, а не основание
копировать секреты, создавать новую установку или расширять права автоматически.
Результат выкладки проверять по GitLab job, версии контейнеров и health портала.
Логи CI не должны содержать значения секретов.

Консоль контейнера приложения и SFTP остаются отдельными способами диагностики
и передачи файлов; они не заменяют запуск job. Прямой SSH-доступ владельцу не
подтверждён.
