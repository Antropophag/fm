## Context

Нормативный контракт: specs/RELIABLE-FIELD-OFFLINE-001.md. Доказанные дефекты и внешние первичные источники: docs/research/reliable-field-offline-browser-practices.md. Пользователь уточнил mine-only. Браузерный cache не обходит корпоративную сеть; server facts по-прежнему создают InspectionRecording/InspectionEvidence.

## Goals / Non-Goals

**Goals:** один shared browser owner очереди для checklist и construction queue, целостная preparation manifest→cache→offline list цепочка, безопасное обновление и recovery.
**Non-Goals:** новый server mutation protocol/schema, работа впервые без предварительной подготовки, native приложение, гарантия против явного удаления данных ОС/пользователем, обход VPN и обязательный Background Sync.

## Decisions

1. Глубокий browser модуль FMonitorField (field-offline.js) владеет local transactions, sequence/lease, wire immutability, transport и photo preparation. Checklist/queue — adapters, не отдельные writers. Он может разделяться на field-offline-store.js / field-offline-sync.js / field-offline-photo.js с одним namespace. Без внешней новой npm dependency. Public integration API: `FMonitorField.open({userId,objectId,projection,onChange}) -> Promise<session>`; session `list()`, `enqueue(type,payload,blob?)`, `sync()`, `retry()`, `discard(id)`, `resolve(id)`, `close()`; `FMonitorField.preparePhoto(file)` и `FMonitorField.pending(userId)`. Snapshot содержит operations, projection, connection/storage state. Implementation author может уточнить форму только согласованно с root tests, не менять контракт.
2. IDB сохраняет прежнее имя fmonitor2-fast-pilot и stores operations/photoBlobs/meta; schema upgrade добавляет необходимые snapshots/manifests/leases, не удаляет v2. Blob+operation+scope sequence коммитятся вместе. UUID и first-attempt payload фиксируются до network. Все новые операции связываются predecessor; у уже отправленного payload ни одно поле не меняется. Older unknown v2 replay неизменен; conflict recovery только явным новым намерением. Receipt+projection+blob release атомарны. Для local ordering использовать sequence, не случайный UUID или IDB enumeration.
3. Fresh authenticated context подтверждает actor+csrf+projection. Строгий server revision сохраняется: цепочка собственных ack продвигает базу только ещё не попытанных действий, внешний conflict требует решения. По одному lease на scope с TTL и token fencing, cross-tab notifications; отдельные scope не голодают. Старый actor после login switch не может послать чужую queue.
4. Protected offline manifest читает существующий authoritative queue owner с ownership=mine, без query, по всем страницам и completed read-only; новых SQL domain writers нет. В payload только нужные metadata и canonical same-origin URLs. Повторный reconciliation набора предотвращает false-ready при перемещении pagination. Подготовка — bounded concurrency2, durable completed count, resumable missing-only и обновление свежести. JSON/HTML private reads no-store на сервере.
5. Worker хранит private cache по user identity и shell по generation, обслуживает offline list/checklist, network timeout3сек до кеша и 5xx fallback, но не auth denial. Shared UI coordinator `field-offline-preparation.js` обеспечивает manifest traversal/readiness/offline list. Offline shell не содержит user secrets: берёт только выбранный authenticated identity bucket. Нельзя доверять произвольному postMessage userId или URL для раскрытия чужого кеша. Logout очищает active identity и private accessibility, не pending queue.
6. PWA start_url=/pilot/construction-control, scope=/pilot/, PNG icons и manifest выдаются через asset/controller routes, CSP без unsafe-inline и внешних origin. Shared shell сохраняет нужные версии ресурсов до безопасной замены. Установка по пользовательскому действию. Нет нового сервера background jobs. Background sync не требуется для correctness: foreground retry/visibility/online/manual работают независимо.
7. Photo decode/resize в отдельном helper с bounded input и memory; EXIF orientation,2560px, target2.5MiB/hard5MiB. Маленькие PNG/WebP допустимо не перекодировать. IDB persistence request и estimate feature-detect; failed write не рисует saved. Cache purge не трогает pending bytes. Local photo download/export recovery; explicit deterministic rejection resolution.
8. UI сохраняет incumbent SHLZ/Golos. Небольшая status область подготовки на queue; локальный список, banner состояния и пооперационные решения в checklist. Не использовать технические ревизии/UUID в пользовательских текстах. Проверить320/390/800/1366px и keyboard/live-region. Root criteria/tests, отдельный executor production/UI.

## Risks / Trade-offs

- Браузер может удалить best-effort storage → persistence request, измерение места, честный статус и export; не обещать абсолютную гарантию.
- iOS/Android suspend фон → correctness при следующем foreground, hardware UNKNOWN до устройства.
- Большой mine-набор → pagination, concurrency2, resumable cache, без скрытого cap; подготовка явно продолжается.
- Session switch и поздние ответы → actor-bound contexts, epoch invalidation и lease fencing.
- Server projection изменится другим актором → явный conflict resolution, не blind rebase.
- Old v2 uncertain queue → точный replay; только definitive conflict можно заменить новым явным намерением.

## Migration Plan

Browser v2 upgrade сохраняет pending/accepted identities и blobs; tests создают старую очередь до новой загрузки. Новая SW version не разрушает old cache до подтверждённого нового shell. Rollback JS не должен удалить v3 данные; документировать совместимость и избегать destructively upgrading stores. Canonical suites.tsv включает новые e2e/integration/worker tests, sensitive policy явно включает new browser paths. Серверные права, audit/time/idempotency неизменны; broad exact-source CI выполняется штатным consumer один раз. Independent Gate3/final — planner-selected, не отменяются.

## Resolved review decisions — before Gate 3

- **Manifest consistency:** authoritative selection is mine AND checklist-readable BEFORE count/pagination, ordered by objectId. Each page returns `setVersion` (SHA-256 of the complete ordered object-ID set). Client requires all pages same version, unique IDs/count equality, then re-reads page1 with the same version. At most3 reconciliation passes per preparation attempt; continued churn gives partial/retry, never readiness or an infinite loop. A new owner read method may select IDs separately from general UI sort. Completed own cases are included only if readable; existing domain completion never becomes editable.
- **Payload shape:** manifest returns metadata/URLs; client performs bounded background GETs of existing server-rendered checklist documents (not browser navigations), no new batch writer or SPA projection renderer. This reuses the actual authorized render/public shell. Research suggestion of batch payload is an alternative, not a normative prohibition on HTTP HTML caching; update note to distinguish. No new mutation request shape, only additive protected-read context and additive reason codes.
- **Context/receipt:** sync-context is JSON `{userId,revision,projection,csrf}` on authorized200. Mutation retains existing status/HTTP mapping and adds stable `reasonCode`: PHOTO_LIMIT_REACHED, PHOTO_INVALID, CSRF_INVALID, ACCESS_DENIED, CASE_NOT_WORKING, STALE_REVISION, OPERATION_PAYLOAD_CONFLICT or generic OPERATION_REJECTED. No SQL/secret detail. Accepted/duplicate retain projection; photo projection supplies matching clientOperationId/id/viewUrl/thumbnailUrl/hash so local receipt can safely free bytes. Semantically generic rejection is not guessed from translation.
- **Identity state machine:** durable active actor is established only from a successful same-origin protected response carrying verified actorId (HTML marker or context JSON), never arbitrary message data. Local epoch monotonically advances on logout/user switch. Logout immediately writes a tombstone and invalidates accessible private documents before waiting for server response; pending queues remain actor scoped. A tombstone cannot be cleared by a late GET/warmup; only a confirmed new login or explicitly authenticated foreground session establishment following that login. Every warmup/cache commit compares captured actor/epoch/generation; mismatch drops response. Offline boot with tombstone shows login/preparation explanation, no past private list. On successful refreshed mine manifest, removed own objects are no longer listed/prepared for new local work; their pending operations remain in a separate recovery list and still require server authorization. Incomplete manifest never purges the previous good set.
- **Legacy recovery:** v2 records keep id/clientOperationId/deviceInstallationId/deviceTime/type/base and business fields. Derive a frozen semantic wire object using the previous serializer's exclusion rules, not byte-identical JSON whitespace. queued/sending/retryable without an attempt marker are conservatively potentially sent: preserve numeric bases, never synthesize chains across them. Deterministic ordering uses existing batch sequence, then deviceTime, then id tie-break; uncertainty is explicit rather than invented. Missing/corrupt photo blob becomes storage-recovery blocked, with export of available metadata and no fabricated bytes/hash. accepted legacy records lacking a matched server photo receipt retain bytes until reconciliation; known accepted records never resend domain effects. No old store is dropped. New clients recognize extra fields; old v2 open requests are version-blocked, close on versionchange and show reload notice; rollback requires compatible reader, not opening version2 destructively.
- **Local transitions:** queue transaction allocates monotonic sequence, reserves capacity, saves predecessor, operation and Blob atomically; wire remains null until dispatch is eligible. Separate dispatch transaction verifies lease, resolves predecessor ack, writes immutable wire and attempted=true/status=sending before network. Failure receipt/retry state is durable before timer/UI. Accepted transaction stores receipt/projection/server photo link and status, then releases only matched acknowledged Blob in that same transaction. Crash before queue commit leaves no operation; after queue commit restores queued; after dispatch commit retries exact wire; after remote commit/before receipt commit repeats exact wire; after receipt commit never replays accepted as new work. Notifications are hints; readers re-query durable state.
- **Lease:** per user/device/object IDB transaction compare-and-set owner random token and expiration45sec; renew every10sec, bounded30sec upload. Verify token and unexpired lease in transaction immediately before dispatch and before committing results. On lost ownership, response is ignored locally and next holder safely replays identical frozen ID/payload. Clock moving backwards is capped using acquisition time/defensive expiry; implausible lease times allow conservative recovery after45sec observed local wait. A stale holder may still reach server: exact server idempotency and persisted wire/predessor ordering, not a client-only fencing token, guarantee one fact. Web Locks can additionally coordinate supported browsers, never sole correctness mechanism.
- **Photo reservation:** same enqueue tx counts latest durable accepted projection plus active local intents, deduplicated by operation/photo identity. queued/sending/uncertain consume slots; definitive rejected/conflict and discarded/superseded do not; server active photos count once. Two concurrent selections cannot both reserve slot10. UI serializes resize to limit memory. No accepted photo is deleted by local discard.
- **Conflict actions:** retry() touches only retryable/uncertain transport states, never conflict/rejected. resolve(id) requires fresh matching-actor context and explicit user review/confirmation; original is definitive conflict/rejected, never uncertain. It creates a new UUID with fresh base and new deviceTime, retains original record/time/payload with supersededBy, and links only never-attempted dependents to replacement. Dependents with frozen wire remain unchanged and individually require recovery. discard requires confirmation and cascades only never-attempted dependents, showing exact affected count; any attempted/uncertain descendant blocks destructive discard until resolved. Replacement photo reuses verified bytes while preserving old rejected history metadata. Applying stale installer/correction requests reruns server invariants, never blindly overrides accepted work.
- **Offline representation:** `/pilot/construction-control/offline` is a non-personal shell; it renders only the current verified actor's durable prepared manifest from IDB and links to cached private documents. Its search covers all53 in fixture, including pages never visited. SW navigation on queue/start_url falls back to this shell; direct checklist falls back to canonical private path across aliases. The online queue readiness panel reads the same durable preparation record, not the visible rows. Existing online filter/inspection-plan code remains operational.
- **Preparation record:** IDB entry keyed actor/device with expected sorted IDs/setVersion/epoch, per-document URL+content hash+cachedAt+shell generation, errors, total and completed status. Put Cache Storage document first; then commit per-document durable success, checking epoch again. If metadata fails, the orphan cache is not counted ready and can be retried. If cache is missing/evicted while metadata exists, startup revalidates and downgrades readiness. Final ready requires full expected set and shell resources actually present. No cache cleanup may delete operations/photoBlobs.
- **Worker generation:** shell resource URLs already content-versioned through AssetVersion. Cache mandatory exact referenced assets and transitive JS dependencies before ready. Use cache-first for versioned immutable URLs; never replace old URL bytes with newer version bytes. A new install failing any required resource is not active/ready. Retain prior compatible shell/private docs; no activate bulk-delete of all prior docs. Retire recoverable old generations only after no live client references them and no prepared document needs their resource versions; explicit user cache cleanup remains independent of pending data. Do not blindly skipWaiting/claim over incompatible open IDB clients; update prompt/reload and migration first. Logout epoch invalidation precedes all generation cleanup.
- **Network outcomes:** timeout/network/408/429/5xx are uncertain/retryable, immutable replay; parse only expected JSON with required fields.401/login redirect/HTML→auth-required;403→access-denied,403 must not erase pending data. CSRF_INVALID obtains fresh context before exact retry, bounded once before asking login.409→explicit conflict;422/400 deterministic validation→rejected reason. Persist nextAttemptAt/attemptCount with exponential2..60sec jitter; cap Retry-After60sec. photo abort30sec; preparation/context/ops15sec; SW navigation races3sec then cached response while late private writes remain actor/epoch fenced.

## Shared engine integration contract

`FMonitorField.open(options)` async; `session.list()` async returns current actor/object operation records with restored local previewUrl where a saved Blob exists; `session.enqueue(type,payload,blob?)` resolves after local commit only (never waits for network), schedules sync, and returns saved operation. `session.sync()`/`retry()` async share same durable lease. `session.discard(clientOperationId)` and `resolve(clientOperationId)` are called only after adapter presents confirmation/fresh context; resolve may fetch that context itself. `session.export(clientOperationId)` returns `{blob,name}` for selected local photo, or explicit metadata JSON for a nonphoto intention; UI does not imply that JSON alone backs up photo bytes. `close()` removes listeners/timers/releases owned lease without deleting records. onChange snapshot: `{operations,projection,connection,storage}`; connection has state=online/offline/sending/retryable/auth_required/conflict, human-safe message and nextAttemptAt when relevant. Source of true accepted state is durable receipt; cached initial projection loses to higher matching saved accepted revision. Integration may enrich optional fields without altering canonical mutation payload. `FMonitorField.preparePhoto(file)` async returns `{blob,name,mime,size,sha256}`; store must reserve cap inside atomic enqueue independently of the UI. `FMonitorField.pending(userId)` async summarizes only matching actor queues. Optional lifecycle/logout helpers remain in facade; adapters never write stores directly.

### Integration correction protocol — complete lifecycle matrix

The second implementation review exposed incomplete lifecycle composition. The following is one coherent correction of the existing A2/A8 contract, not additional product scope.

1. **Worker build ownership.** The server emits an immutable build generation (aggregate SHA-256 of the exact shell asset manifest) in the worker response. A worker uses its own build's shell/document cache, never a mutable global pointer to resolve its assets. Install fetches all mandatory exact URLs into that build's staging cache; only successful activate publishes that build as active and appends its generation to the retained generation history. A failed install or waiting build must not change the active pointer or active bytes. Identity/tombstone/login proof live in a version-independent metadata cache. Worker restart hydrates epoch from durable identity; epochs never regress.
2. **Every authenticated shell.** ViewSupport and the four custom logout views (objects, calendar, users, roles) expose the trusted actor marker and register one shared Store/lifecycle coordinator. The lifecycle owns a single readiness promise for initial identity, the actor-bound login-proof handshake, update gating and logout. Checklist and preparation await it before opening sessions or rendering private offline data. Successful explicit login at the default objects destination is enough for subsequent direct-checklist recovery. Ordinary GET must never clear a tombstone.
3. **Update handoff.** A waiting worker never claims old clients. All authenticated pages observe registration/update state and show a clear close-old-tabs/reopen instruction before upgrading a legacy database while incompatible clients remain. No silent loss, automatic deletion or half-installed readiness. The active pointer changes only at activation; a cold start then promotes last-known-good documents to the complete current script set (including lifecycle), retaining original bytes. Generation history and cached-document timestamp/hash determine newest compatible selection; search both legacy checklist and prior field generations.
4. **Preparation refresh and recovery.** Read previous durable preparation first. For every currently assigned manifest ID, verify the saved URL/hash against the active or promoted cache. Retain each valid previous document as available while attempting an online refresh. A failed refresh preserves that document and its timestamp/hash with an explicit stale/refresh-error state, leaves the overall preparation partial, and keeps the object usable offline. New/missing documents remain unavailable until both cache and fenced metadata commits succeed. A subsequent explicit retry resumes the incomplete work. Assignment removal changes the current list without deleting pending intentions. Never replace a good complete record with empty pending/error-only metadata.
5. **Logout under storage failure.** Hide private UI and close local sessions immediately after explicit confirmation. Request/ack the SW tombstone independently of IndexedDB; attempt the IDB epoch/tombstone transaction. Even if storage fails, submit server logout in finally, retain an honest cleanup-error notice where navigation fails, and never silently leave the button inert. Offline-shell rendering requires both durable IDB actor and worker identity agreement.
6. **Atomic section-completion intent.** Inside the shared operations transaction, reject/reuse an already-live section_completed for the same scope/section, and recognize an already completed durable projection. The UI's tab-local flag is only a rendering aid. Preserve the incumbent legacy-operation permission gate, bulk confirmation dialog and photo-before-section dependency chain.

Root owns regressions for the custom-object-list logout, direct-checklist login recovery, generation activation/identity persistence, exact versioned resources, cold v8 promotion, partial-refresh last-known-good list and two-tab section deduplication. No implementation author edits these tests. All original review findings remain open until corrected and independently verified; passing narrower HTTP/worker tests does not approve the complete lifecycle.

A7 review completion: `session.review(clientOperationId)` is a read-only fresh actor-bound projection plus selected immutable local intent and opaque review revision. The UI names the affected item/section/photo and shows current server item states before confirmation; raw revisions and wire fields are not product copy. `resolve(id, reviewedRevision)` cannot silently adopt a different unreviewed server base: it either creates the replacement against the reviewed revision or asks the user to refresh/review changed state. Login-proof confirmation is idempotent only for the exact still-unconsumed actor/device/nonce and exact already-active SW identity; logout/consumed proof cannot be replayed. Proof removal follows durable SW identity write, so a lost acknowledgement can be resumed locally without another login.

### Surviving-cookie reauthentication correction

Inspection of the actual AuthController found its existing authenticated-cookie early redirect precedes all password verification. A failed offline logout therefore prevents GET login from showing a form, and a password-bearing POST can redirect without checking credentials. The bounded correction retains the ordinary authenticated GET redirect, but makes explicit credential POSTs use the existing CSRF/password/rate-limit path and exposes GET `/pilot/login?reauth=1` using the existing form. Both offline-shell and private-identity error UI link to that recovery route. No new session token, authentication store, password policy or domain writer is introduced. Root HTTP and end-to-end recovery assertions are deliberately RED until this correction; the other mapped tests are GREEN regression controls for this incremental Gate3. Original Gate3 RED history remains in the immutable first package/review record.
