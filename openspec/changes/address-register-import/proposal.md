## Why

FMonitor нужен повторяемый импорт адресного перечня из XLSX: новые объекты появляются в каталоге, повторные файлы дополняют реквизиты, адреса проверяются через ДаДату внутри импортного процесса. Разовый перенос 2027 года не решает последующие загрузки и не обеспечивает понятную историю изменений.

## What Changes

- Один вертикальный срез `ADDRESS-REGISTER-IMPORT-001`: операторский CLI и публичный application seam `AddressRegisterImportApplication` с операциями preview/apply/resume.
- Профиль текущего адресного перечня: явные год и договор, проверка структуры независимо от Excel-фильтра, сохранение исходных строк и нормализованных значений.
- Объекты создаются в каталоге с пустыми плановыми датами без нового процессного статуса и без открытия работ.
- По умолчанию заполняются только неизвестные поля. Отличающееся заполненное значение сохраняется с предупреждением; ноль, «нет» и осознанное ручное очищение не считаются отсутствием данных.
- Универсальный `--overwrite` заменяет заполненные импортируемые реквизиты, включая ручные, только после preview и с причиной. Пустые ячейки не очищают БД даже с этим флагом.
- ДаДата стандартизирует адреса в ходе подготовки пакета. Принимается подтверждённый дом; исходный адрес, ФИАС ID, качество и происхождение сохраняются вместе.
- По уточнению владельца используем платный clean/address с минимизацией расходов: долговечный межпакетный кэш, перенос проверенных ответов dev → prod, бесплатная локальная оценка и явный лимит платных попыток. Повторный импорт и overwrite сами по себе не обновляют адресную проверку.
- Ошибка структуры, строки, адреса или идентификации блокирует весь пакет. Применение всех изменений каталога и их аудита атомарно; подготовительный журнал сохраняется и при отказе.
- Долговечные пакет/операция, защита от дублей, конкурентных изменений и неизвестного результата commit; возобновляется подготовка, а не частичная публикация каталога.
- Русская сводка и подробные CSV/JSON-отчёты с причинами и дальнейшими действиями; потоковая обработка и порционное хранение поддерживают реальный объём перечня при штатных 256 MiB PHP и 16 MiB DB packet.

Источник требований: решения владельца в текущей беседе 2026-11-18. Oracle структуры — приватный XLSX адресного перечня (срез 2027: 2668 лифтов / 667 UNOM); реальные строки и адреса в Git не копируются. Синтетические acceptance-примеры определяются контрактом, не существующим импортёром.

Не входят: произвольные Excel-форматы, отдельный шаблон дозаполнения, новый UI импорта/редактор полей, автоматическая загрузка в prod, пересоздание существующих дел, перенос процессной истории, изменение финансовых формул, очистка полей пустотой и автоматическое объединение неоднозначных объектов.

## Capabilities

### New Capabilities

- `installation/address-register-import`: повторяемая атомарная загрузка адресного перечня с проверкой ДаДатой, дозаполнением/overwrite и аудитом.

### Modified Capabilities

Нет существующего main OpenSpec для этого CLI. Интеграция чтения объектов с пустыми датами и общий доступ к актуальным реквизитам описаны в новой capability; действующие основания процессных действий не ослабляются.

## Impact

- Owning module: InstallationProcess; Yii console — тонкий adapter. Новую логику в rapid-pilot не добавлять.
- Аддитивные миграции каталога, адресного evidence, планируемых технических характеристик, договорных реквизитов и журнала импорта; версии назначить по актуальному schema frontier.
- Адаптер XLSX, серверный ДаДата clean/address, секреты окружения, HTTP timeouts/retry, приватное хранение источников и отчётов.
- Каталог/карточка должны читать загруженные объекты без обязательного графика; существующие ручные значения имеют ту же эффективную проекцию, что и импортируемые.
- Runtime/deployment/readiness, backup/restore, архитектурные границы и Quality Graph требуют проверки до Gate 2.

Статус на 18.11.2026: source/live readiness v39; read-only census dev/prod выполнен, подготовлен root executable spec/test candidate и отдельный delivery binding. Первый независимый Gate 3 вернул CHANGES_REQUESTED; реализация не начата. Новое требование экономии требует синхронизации executable spec/tests и свежего review. Прежние delivery-задачи не меняются.

Ключи найдены в legacy, выполнен только разрешённый read-only запрос баланса. Владелец отдельно получает разрешение владельца аккаунта; до явного сообщения о нём платные вызовы, перенос ключей на стенды и испытание реальных адресов не выполняются. Исследование бесплатного ФИАС сохранено как альтернативное исследование, оно не меняет выбранный provider.

Коррекция 19.11.2026 по final review v1: небольшой synthetic suite прошёл, но пакет 2668/667 выявил OOM при хешировании полного отчёта и превышение DB packet. В неопубликованной v40 добавляется седьмое семейство ограниченных payload chunks (113 таблиц / 60 AUTO_INCREMENT); внешние команды, полный JSON/CSV, атомарность и правила расходов сохраняются. Ранее утверждённая упаковка целого отчёта в один JSON-параметр больше не принимается. CLI unknown commit требует exit75. Реализация корректируется после новых root regressions и независимого Gate3; предыдущие reviews сохраняются.
