# Операционная передача: пароль и email recovery

Этот документ описывает требования к будущему развёртыванию. В текущей задаче серверы, реальные пользователи и почтовые ящики не изменяются; operational status — UNKNOWN до отдельной проверки целевого контура.

## Конфигурация

Обычный вход и первое назначение пароля не требуют почтовой отправки. Для восстановления нужны действующие SMTP-настройки, HTTPS `FMONITOR_PUBLIC_BASE_URL`, `FMONITOR_PASSWORD_RECOVERY_KEY` (base64 от32 криптографически случайных bytes) и стабильный `FMONITOR_PASSWORD_RECOVERY_KEY_ID`. Значения ключа и SMTP password хранятся только в приватном env/secret store, recovery key/keyId доступны PHP-приложению и delivery worker. SMTP-конфигурация также нужна jobs-scheduler для включения outbox/weekly scheduling; ключ восстановления ему не передаётся. Prepare/migrate/startup-check/local-integration/nginx/MariaDB не получают эти секреты. Ключ должен сохраняться между restart/update, в исходники/логи/скриншоты его не включать. Письма доставляются штатным jobs-worker после commit; наличие SMTP-конфига без работающего worker не доказывает доставку.

Без recovery конфигурации пользователь получает безопасную недоступность восстановления; обычный вход остаётся доступным. Частичная/непригодная конфигурация не заменяется plaintext fallback. Real smoke выполняется только на явно выбранном тестовом адресе по отдельному поручению; fake transport evidence не означает live email GREEN.

## Переход и сохранение

Перед production update читается запись именно нужного контура (dev и production различаются по текущей очереди). Новая canonical migration40 проверяет предшествующие данные; несовместимость блокирует изменение без угадывания роли/активности. Действующие hashes/ID/роли/блокировки/история/legacy links сохраняются. Разрешённые ожидающие приглашения записи переходят в ожидание первого пароля. Старые ссылки прекращают работать и ведут к странице входа, исторические invitation rows сохраняются.

Проверить штатную prepare/check/migrate последовательность, доступность libsodium, одинаковые key ID/key/origin в PHP и worker, отсутствие recovery URL в nginx/application logs. Не отправлять секрет в журнал проверки или вывод Compose при операторской работе. Публичный dump Compose с секретами не публикуется.

## Восстановление и отказ

Backup включает три password/recovery таблицы вместе с остальной canonical DB и сохраняет значения последовательностей. Envelope key резервируется отдельно от DB. Отсутствующий или иной key не разрешает отправку сохранённых grant; после восстановления правильной конфигурации можно запросить новое письмо. Срок grant не продлевается восстановлением backup. Неизвестный SMTP ACK остаётся UNKNOWN_DELIVERY без автоматического повторения; пользователь может сделать новый ограниченный по частоте запрос.

При дефекте recovery endpoint можно временно закрыть с явной недоступностью, сохранив обычный вход. Не запускать старый invitation writer поверх новой схемы и не делать destructive down migration. Отдельный rollback/restore должен сохранять append-only историю и последнее состояние доступа.
